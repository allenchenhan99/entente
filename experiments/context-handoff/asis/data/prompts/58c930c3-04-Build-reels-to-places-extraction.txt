## 專案背景
Unvisited 的核心是一道減法：使用者「想去的地點清單」⊖「Google 位置歷史證明已去過的」= 未竟清單。
你負責產出減法的左邊：**把使用者在 Instagram / TikTok 等平台收藏的旅遊短影音，轉成結構化的候選地點清單。**

## 先讀這個檔案（不可修改的契約）
`D:\vscode_python\unvisited\unvisited\schemas.py` — 你的輸出是 `list[Place]`，注意 `confidence`、`needs_review`、`source_excerpt`、`PlaceCategory`。

## 設計前提（請先接受這個判斷，這是 PM 的決定）

這個模組**技術上最脆弱、對產品價值貢獻最小**。社群平台的反爬蟲隨時會變，我們不會投入資源去打這場仗。因此：

- **架構成 provider 介面**，實作多個 provider，任何一個失效都不影響其他
- **必須有一個永遠不會壞的路徑**：使用者手動貼上文字／自行提供地點名稱清單
- 抓不到就明說抓不到，**絕對不要為了讓流程看起來順暢而編造地點**

## 你要交付的東西

### 1. `unvisited/ingest/providers.py`
定義 provider 介面（輸入 URL 或文字 → 輸出原始素材：標題、說明文字、字幕、留言、hashtag、可能的畫面）。

先上網研究 2026 年當前可行的取得方式，把評估結論寫進報告：
- 官方 oEmbed 或公開 metadata（最穩定，優先）
- 第三方服務（例如 Apify 有現成的 actor）
- 使用者自行下載後由本地檔案匯入
- **不需要研究登入態爬蟲，我們不走那條路**

至少實作：一個真的能用的 provider + 一個 `ManualProvider`（使用者直接貼文字）+ 一個以合成素材驅動的 mock provider 供測試。

### 2. `unvisited/ingest/extract.py` — 素材 → 地點
從非結構化文字中抽出地點。這是本模組真正的技術內容。

必須處理的難點：
- 一支影片常包含**多個地點**（「東京必去5間咖啡廳」）
- 地名混雜多語言（日文漢字、假名、羅馬拼音、英文、中文譯名並存，例如「清澄白河 / Kiyosumi-Shirakawa」）
- 大量無關文字（hashtag 洗版、業配聲明、BGM 資訊）
- 只有店名沒有城市，需由上下文推斷
- **分類**：判定 `PlaceCategory`，這會直接影響下游造訪判定的門檻，判錯會導致誤判

實作上可用 LLM 抽取。專案負責人有 OpenAI 與 Anthropic 的使用經驗，請設計成**可抽換的 LLM 介面**並提供一個不需 API key 的規則式 fallback（品質較差但能跑）。API key 從環境變數讀，不要寫死，也不要自己去申請或設定。

### 3. `unvisited/ingest/geocode.py` — 地點名 → 座標
`Place` 沒有座標就無法比對，這步是必要的。
上網研究免費且不需 API key 的方案（Nominatim / OpenStreetMap 是明顯候選，注意其使用政策與速率限制，務必遵守並實作節流與本地快取）。

**關鍵**：查不到或有多個同名結果時，`confidence` 要據實降低，讓 `needs_review` 為 True，交給使用者確認。**寧可回報低信心，也不要猜一個座標** —— 猜錯會讓下游判定「你去過」，那是最糟的錯誤。

### 4. `tests/test_ingest.py`
用 pytest 與合成素材。重點測：一支影片多地點、多語言混雜地名、純 hashtag 無地點、地名有歧義（多個同名結果）、provider 失敗時的行為、分類正確性。
