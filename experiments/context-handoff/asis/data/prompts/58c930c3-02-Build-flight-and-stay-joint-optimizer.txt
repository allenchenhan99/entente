## 專案背景
Unvisited 幫使用者找出「想去但還沒去過」的地點，然後回答：**哪個日期區間、住在哪一區，機票加住宿的總花費最低、又能覆蓋最多未竟地點？**

關鍵洞察（這是本模組的賣點）：市面上都是分別挑最便宜的機票、分別挑最便宜的旅館，然後相加。但這兩者互相牽動 —— 晚三天出發機票省兩千，旅館卻因週末漲三千；住近郊房價低，但每天多花的交通費吃掉價差。**分開最佳化的結果加起來不是最佳解。** 我們要聯合求解。

## 你要交付的東西

### 1. `unvisited/optimize/flights.py`
- 查詢去回程航班，支援固定日期與**彈性日期區間**（給定旅遊天數與可接受的出發區間，自動配對所有去回組合）
- 廉航行李費必須計入 `total_cost`
- 每筆結果填好 `fetched_at`
- 需有本地快取層（檔案快取即可），避免開發與 demo 時反覆打外部服務被限流

### 2. `unvisited/optimize/stays.py`
- 查詢住宿。先上網研究哪個資料源最可行（無需 API key、不會被擋、可程式化取得）。若找不到穩定免費來源，**設計成 provider 介面**，實作一個可用的 provider + 一個以合成資料驅動的 mock provider，並在報告中說明你的評估。
- 關鍵：住宿不是只比價，要能依「**落腳區域**」聚合 —— 我們要比較的是「住在新宿 vs 住在淺草」而不是個別旅館。

### 3. `unvisited/optimize/combo.py` — 核心
聯合最佳化。輸入：未竟地點清單（含座標）、出發地、可接受日期區間、旅遊天數範圍、總預算上限。
對「出發日 × 回程日 × 落腳區域」的組合空間求解，目標函數同時考慮：
- 機票 + 住宿 + **區內交通成本**（依落腳點到各未竟地點的距離估算，這是讓「住近郊比較便宜」這個假象破功的關鍵）
- 未竟清單覆蓋率（在合理單日移動範圍內能排進行程的地點數）

輸出**帕累托前緣**上的數個方案，各自標記 `pareto_tag`：`cheapest` / `fastest` / `max_coverage` / `balanced`。不要只回傳單一最佳解 —— 省錢、省時、覆蓋最多三者互相衝突，取捨屬於使用者。

組合空間可能很大，注意效能：先做候選剪枝再求解。

### 4. `tests/test_combo.py`
用 pytest 與合成資料。重點測：帕累托前緣正確性（不應有被支配的解混進來）、預算約束、日期邊界、空輸入、單一地點、所有航班都超預算時的行為。
